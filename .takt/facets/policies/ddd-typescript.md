# DDD TypeScript ポリシー

ほかの DDD ポリシーの規則を TypeScript のコードでどう判定するかと、TypeScript だけの規則（コード表現、イミュータブル、`Result` の置き場所、パッケージ境界、検査できる構文）を定める。読み替えた結果が規則に反すれば、その規則の判定になる。モジュール配置はモジュール配置ポリシーが持つ。

## 規則の読み替え

| 規則（ポリシー） | TypeScript での判定 |
|------------------|----------------------|
| 状態を公開しない（ドメイン層） | 状態は `#` フィールドかファクトリのクロージャに持つ。それ以外のプロパティ（`private`、`protected`、`readonly`、パラメータプロパティを含む）は公開とみなす |
| 型の外で組み立てない（ドメイン層） | class 表現では、`new` はその型自身の class 本体の中にだけ書く。companion 表現では、インスタンスは完全コンストラクタのファクトリの中でだけ書き、スプレッド、`as`、`satisfies` で作らない |
| 完全コンストラクタを通す（ドメイン層） | class 表現では、`private` のコンストラクタが状態全体を受け取る。companion 表現では、状態全体を受け取るファクトリ（`restore`）が完全コンストラクタで、ほかのファクトリとコマンドはそれを通す |
| その場で変えるか、新しいインスタンスにするか（ドメイン層） | 新しいインスタンスにする。下の「イミュータブル」に従う |
| 業務上の失敗は Result で返す（ドメイン層） | 想定された失敗は `{ ok: false, error: "<case>" }` で返す。操作のエラー型は、その操作の case の文字列だけからなる export された union |
| 宣言との一致（ドメイン層） | 写像されたファクトリとコマンドは、戻り値の型に `Result<success_type, error_type>` を明記する。ファクトリの成功値は集約の型。操作に結び付かないファクトリ（`restore`、値オブジェクトの `of`）は値そのものを返してよい |
| 重複成功（ドメイン層の冪等性） | 成功値の型に `kind: "applied"`（新しいインスタンスとイベント）と `kind: "duplicate"`（変わらないインスタンスだけ）を持たせる |

## コード表現

| 基準 | 判定 |
|------|------|
| 集約、Entity、Domain Primitive、値オブジェクトが、`.ddd.toml` で選んだ表現（`class` か `companion`）と違う表現で書かれている | REJECT |
| ドメインの class がアクセサ（`get`/`set`）、`extends`、`implements`、デコレータ、`declare`、`abstract` メンバー、計算メンバー名を使っている | REJECT |
| companion のドメイン型が、1 つのファイルの中で同名の `type T = { … }` リテラルと `const T = { … }` の組になっていない、または `interface` と `const` の組になっている | REJECT |
| companion の型リテラルがブランドとメソッドシグネチャ以外を持っている、またはブランドのキー `[brand]` 以外の計算メンバーがある | REJECT |
| companion の型が、export しないトップレベルの `const brand: unique symbol = Symbol("T")` を持たない、`Symbol.for` を使う、またはブランドを export している | REJECT |

## イミュータブル

参照が自由に共有されるので、集約と Entity を含むドメインのインスタンスは組み立てた後に変えない。コマンドは、変更後の状態で完全コンストラクタから新しいインスタンスを組み立てて返す。

| 基準 | 判定 |
|------|------|
| コンストラクタや完全コンストラクタのファクトリの外で、`#` フィールドやクロージャの状態に書き込んでいる（コマンドや replay メソッドの中を含む） | REJECT |
| 状態に対して変更系のメソッド（`push`、`splice`、`sort`、`set`、`add`、`delete`）を呼んでいる | REJECT |
| `#` フィールドが `readonly` で宣言されていない | REJECT |
| コマンドの成功値の型が、新しいインスタンスとイベントの両方を持たない（`Result<void, E>`、`Result<Invoice, E>`） | REJECT。両方を持つ型（`IssueInvoiceOutcome`）をエラー型と並べて export する |
| ユースケースが、コマンドの返したインスタンスではなく、読み込んだインスタンスを保存する、または使い続ける | REJECT |

## `Result` の置き場所

| 基準 | 判定 |
|------|------|
| ドメインのパッケージが独自の `Result` を宣言している、または Result のライブラリ（neverthrow、Effect、fp-ts）を使っている | REJECT |
| ドメインのパッケージが `Result` を、`dependencies` に挙げた言語拡張パッケージから、パッケージ名と `import type` で読み込んでいない | REJECT |

## パッケージ境界

| 基準 | 判定 |
|------|------|
| 他のパッケージに、相対パス、`paths` のエイリアス、`exports` が公開していないサブパスで到達している | REJECT |
| `tsconfig.json` が `baseUrl` や、他のパッケージへの `paths` を設定している | REJECT |
| パッケージのエントリが `export *` を使っている | REJECT。名前を 1 つずつ公開する |
| パッケージ内の相対指定子が `.ts` 拡張子を省いている | REJECT |

## 検査できる構文

| 基準 | 判定 |
|------|------|
| ドメインのソースが、分割代入、オブジェクトスプレッド、デコレータ、`import =`、`export =`、動的 `import()`、namespace、動的な呼び出し先を使っている | REJECT |
| オブジェクトリテラルに、ドメインの型を含む複合型（`{ lines: readonly InvoiceLine[] }`、`Record<string, Invoice>`）の注釈を付けている | REJECT。コレクション自身の変数に注釈を付ける |
| ドメインのメソッドの受け手、ユースケースの `execute` の引数、`execute` や getter の受け手に、1 つの型を名指す注釈がない | REJECT |
