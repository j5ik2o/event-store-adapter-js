# DDD ドメイン層ポリシー

ドメイン層のコード（集約、Entity、値オブジェクト、Domain Primitive、イベント、ドメインサービス）を判定する。宣言との一致、組み立てと復元、状態の変更、冪等性、判断の置き場所、業務上の失敗を扱う。ユースケースのコードの判断の置き場所も、このポリシーの「getter と判断」で判定する。言語での書き方は言語ポリシー、宣言の書き方はドメインモデルポリシーが持つ。

## 宣言との一致

| 基準 | 判定 |
|------|------|
| コードの型、フィールド、メソッド、エラー型とその case、成功値の型、イベント、replay メソッドが、ドメインモデルと集約写像の宣言と一致しない | REJECT。宣言に合わせる。宣言が誤っているなら、先に宣言を直す |
| 宣言にない業務操作、ドメインエラー、不変条件、状態、イベントをコードで作っている | REJECT。先に宣言する |

## 組み立てと復元

| 基準 | 判定 |
|------|------|
| ドメインの状態が公開フィールドで外から読み書きできる | REJECT |
| 集約や Entity を、どの層のコードであれ、その型の外でリテラル、既定値、キャスト、公開コンストラクタで組み立てている | REJECT。状態全体を受け取る完全コンストラクタを通す |
| ファクトリが入力を検証する前にインスタンスを作る、または空のインスタンスを作って後から埋める | REJECT |
| `init`、`setup`、`initialize`、`reset`、`configure` のメソッドで組み立てを完了させている | REJECT |
| 永続化された状態を restore ファクトリ以外で組み立て直している、または restore ファクトリが状態全体を検証しない | REJECT。状態全体を検証して完全コンストラクタで組み立てる restore ファクトリを、アダプタから呼ぶ |
| restore ファクトリが壊れた状態を throw で拒否する | OK。壊れた状態は業務上の失敗ではない |
| 操作に結び付いたファクトリが、宣言済みのエラーがあるのに値そのものを返している | REJECT |

## 状態の変更とイベント

| 基準 | 判定 |
|------|------|
| 集約ルートの状態を変えるメソッドが、宣言済みコマンドのメソッドでも、宣言済みの replay メソッドでもない | REJECT。集約の中の値、Entity、コレクションを変えるメソッドは、コマンドから呼ばれる部品であり、コマンドではない |
| setter や汎用の更新メソッドがある | REJECT |
| 名前（`apply`、`on_event` など）だけを根拠に replay メソッドとして扱っている | REJECT。replay は `replay_methods` に宣言したメソッドだけ |
| replay が新しい業務判断をする、または保存済みイベントを業務上の失敗として拒否する | REJECT。replay は事実を適用するだけ。壊れた履歴は復元を中止する |
| ドメインの型（集約、Entity、値オブジェクト、Domain Primitive、コレクション）を、その場で変えるか、新しいインスタンスにするか | 言語ポリシーが決める |
| 内部可変性や共有参照で業務上の状態変更を隠している | REJECT |
| 状態を変えるコマンドが、生んだ 1 つのイベントを返さない、またはイベントのリストを返す | REJECT。宣言した `event` を 1 つ返す |
| 業務上の失敗を検出する前に状態を変えている、または失敗したコマンドがイベントを返す | REJECT。先に確かめてから変える。失敗したコマンドは何も変えない |

## 冪等性（`command-id-memory` のコマンド）

| 基準 | 判定 |
|------|------|
| 集約が記憶するコマンド ID が、コマンドの宣言した `retention` に従っていない（`last-one` は最後の 1 件、`multiple` は直近の `retention_count` 件、`time-window` は `retention_window` の間） | REJECT |
| 反映済みのコマンド ID を、状態や不変条件による拒否より後で判定している | REJECT。記憶したコマンド ID を最初に判定する |
| 反映済みのコマンド ID の再試行で、状態を変える、イベントを返す、または拒否を返す | REJECT。何も変えず、イベントのない重複成功を返す |
| 拒否したコマンドの ID を記憶している | REJECT。記憶するのは反映したコマンドだけ |

## getter と判断

| 基準 | 判定 |
|------|------|
| ドメイン層やユースケース層のコードが、ドメインオブジェクトの状態を getter で読み、比較・計算・分岐に使っている | REJECT。その状態を持つオブジェクトの操作に判断を移す |
| ユースケースのコードが getter の結果を、そのまま、または不変のローカル変数経由で、リポジトリポートのメソッドの引数に渡す | OK |
| 表示や永続化のために、問い合わせメソッドが複製か読み取り専用の値を返す | OK |

## 業務上の失敗

業務上の失敗は操作の契約の一部である。業務ルール違反で例外を投げるという一般的な指針は、ドメインの操作には当てはまらない。

| 基準 | 判定 |
|------|------|
| コマンドやファクトリが、想定された業務上の失敗を throw で伝えている | REJECT。操作固有のエラー型を持つ Result で返す |
| 操作のエラー型に別の操作の case が含まれる、または文字列、`any`、`unknown`、何でも入るバリアントに広げている | REJECT |
| 1 つのエラー型を複数の操作で共有している | REJECT |
| 想定外の実行時エラーや壊れた状態を throw や panic で扱う | OK。それらは業務上の失敗ではない |

## 値、Entity、コレクション

| 基準 | 判定 |
|------|------|
| 業務上の意味を持つプリミティブ（金額、識別子、数量）を、裸のプリミティブのままドメインの境界を越えて渡している | REJECT。Domain Primitive で包む |
| 値オブジェクトが同一性で等価を判定している、または Entity が値で等価を判定している | REJECT |
| 外からの値で Domain Primitive を組み立てるファクトリが、宣言した値の規則を確かめずに受け入れている | REJECT。規則に反する値は、そのファクトリのエラーとして Result で返す |
| ドメインの型が、ほかの状態と並べてコレクション（配列、`Set`、`Map`、`Vec`、`HashSet`、`HashMap` など）を裸のまま持っている | REJECT。ファーストクラスコレクションの型で包み、コレクションへの操作と判断をその型に置く。状態がそのコレクションだけの型が、ファーストクラスコレクションである |
| ドメインサービスが状態を持つ、永続化する、または集約が持てる判断をしている | REJECT |

## 所有

| 基準 | 判定 |
|------|------|
| 受け取った可変の配列、マップ、オブジェクトを複製せずに持っている | REJECT |
| 状態として持つ可変のコレクションやオブジェクトをそのまま返している | REJECT。複製か読み取り専用の値を返す |
